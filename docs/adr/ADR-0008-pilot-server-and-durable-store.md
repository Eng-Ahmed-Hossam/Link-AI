# ADR-0008 · Concierge pilot: one laptop server, JSON snapshot + append-only log, PIN sessions

- **Status:** Accepted for the concierge pilot only (OD-50). Not the product architecture: core-api (ADR-0001, ADR-0003, ADR-0006) replaces it after Demo Day.
- **Date:** 2026-10-04
- **Deciders:** Founder (task owner); implemented in `apps/pilot`

## Context

The pilot (OD-50) needs real staff to use the follow-up loop for 5–7 days at one centre, starting as soon as possible. core-api does not exist yet; the follow-up domain exists as a tested in-memory module (`packages/mocks/src/followup`, 54 rule tests, 100+ e2e tests across three apps). The mock server keeps state in memory, accepts `mock.<userId>` tokens and serves demo routes, so it cannot be used with real people as it is.

Requirements: nothing lost on a restart or a power cut; append-only activity history for the metrics; per-person sign-in with lockout; no demo route, fixture or demo user reachable; HTTPS on the centre LAN so phone browsers allow the microphone; runs on a Windows laptop with no cloud, no Docker and no paid service.

## Decisions

| # | Decision | Why |
|---|---|---|
| 1 | **Reuse the follow-up domain module**, generalised from one demo group to a *world* (centre, groups with weekly schedules, students, guardian labels, staff). Demo mode builds the world from the fixtures (behaviour unchanged, all existing tests pass); pilot mode stores the imported world in its state. | One implementation of the trust rules (only confirmed records trigger rules, block-never-cap, idempotent confirm, dedupe, approval) instead of a second copy for the pilot. |
| 2 | **Store: one JSON snapshot (`state.json`) written atomically after every change, plus an append-only activity log (`activity.jsonl`).** Write a temp file, fsync, rename (retried on Windows `EPERM`/`EBUSY`). Each new activity event is appended and fsynced after the snapshot that contains it; on start, events in the snapshot that the log lacks are appended, so the log never misses one. | No native dependency (SQLite drivers need a compiler or prebuilt binaries on Windows). State is small (one centre, a week). A crash leaves the old or the new snapshot, never a half-written one. Tested by killing the server process (`SIGKILL`) during a burst of writes: every acknowledged write survives. |
| 3 | **Backups:** a copy of both files every hour and on every shutdown, into a folder on the same encrypted drive; the newest 48 are kept. `pilot:restore` backs up the current data before restoring. | Covers operator mistakes (wrong import) and disk-level corruption of the newest copy. |
| 4 | **Sign-in: name + 6-digit PIN**, set by the owner and shown once. scrypt hashes with a per-PIN salt; 5 wrong PINs lock that person for 15 minutes; 30 attempts per address per 15 minutes. **Sessions are server-side**; the browser holds only an opaque token in an `HttpOnly; SameSite=Strict` cookie (`Secure` on HTTPS). No PIN or token in localStorage. `mock.<userId>` tokens are never accepted. | Staff share devices and have no work email; PINs are what they can use. Server-side sessions can be revoked at once when the owner removes someone. |
| 5 | **One origin per app:** the pilot server serves the API (`/v1/*`) and the app on the same origin — the owner web on port 8443 (proxied to the Next.js production build on 127.0.0.1) and the teacher app's static web export on 8444. CORS is an explicit allow-list; every other origin gets 403. | Same-origin cookies, no CORS credentials dance, no token in JavaScript. |
| 6 | **HTTPS on the LAN with a local CA** generated by `pnpm pilot:cert` (node-forge): a CA certificate installed on the 1–2 teacher phones, and a 180-day server certificate for the laptop's LAN address. The server binds to the LAN address only (never `0.0.0.0`), plus plain HTTP on 127.0.0.1 for the laptop itself. | Browsers allow the microphone only in a secure context. Same job as mkcert without installing a separate tool; re-running keeps the CA, so phones stay set up. |
| 7 | **Start-up check:** the server refuses to start unless `LINK_MODE=pilot`, no demo or mock route is mounted, the stored world is a pilot world with no fixture id or demo user, no guardian phone number is stored, no demo setting is present, and the built app bundles contain no demo code (`/__demo/`, demo user ids, mock tokens). Demo code is kept out of pilot builds by aliasing one module (`@demo`) to a stub at build time. | "Don't let the demo reach real people" as a test, not a promise. |
| 8 | **Metrics from the log only** (`pnpm pilot:metrics`): structured `data` on each activity event (ids, dates, channel, result — no names), plus the group schedule. | The append-only log is the evidence; the metrics can be recomputed and checked against it. |

## Consequences

- ✅ The pilot can start with the code that the demo already proved, on a laptop, in a day.
- ✅ Every acknowledged write is durable; backups and a restore command exist; a test proves the kill case.
- ⚠️ One process, one writer: commands that change data (`pilot:import`, `pilot:restore`, `pilot:wipe`) refuse to run while the server runs.
- ⚠️ The whole state is rewritten on each change. Fine for one centre for weeks (tens of KB); not a design for production.
- ⚠️ No RLS, no outbox, no multi-centre isolation: there is one centre. Everything here is replaced by core-api.
- ⚠️ The teacher app's offline drafts on phones are still in browser storage, not encrypted (the existing "not encrypted — placeholder" label); the pilot roster is pseudonymised to limit what that exposes.

## Alternatives considered

- **SQLite (better-sqlite3 / node:sqlite).** Stronger, but a native module or an experimental built-in on the pilot laptop; the gain is small for one centre for one week.
- **The Postgres stack from ADR-0006.** Needs Docker Desktop on the centre laptop and core-api, which does not exist yet.
- **A cloud host on a free tier.** OD-26/OD-31 are open, the pilot data would leave the centre, and free tiers ask for a card.
- **mkcert.** Equivalent; one more tool to install on Windows and its CA install needs admin rights.
