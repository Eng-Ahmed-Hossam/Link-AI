# 13 · Open decisions and conflicts

This file lists every business choice that is still **TBD**. Each one has the default we build with. Every default is **configurable**, so changing it later does not need a code change. Nothing here is a final business decision.

- **Who decides** names a role, not a person. Fill in names at the review.
- **Deadline** names the backlog epic or milestone that needs the answer first (see [12-backlog-phase1.md](12-backlog-phase1.md)). Add calendar dates at the review.
- Part B lists conflicts between the kickoff prompt and the Figma / Eraser sources. The kickoff prompt wins each time.

Status values: `open` · `decided` · `superseded`.

## How to close a decision

1. Write the answer in the row and set Status to `decided`.
2. Update the rule in [01-business-rules.md](01-business-rules.md) and any PRD that points to it.
3. If the answer changes a default value, change the seed or config. Don't change code paths. All of these are settings.
4. If the answer changes architecture, add an ADR in [adr/](adr/).
5. Add a line to [CHANGELOG.md](CHANGELOG.md).
