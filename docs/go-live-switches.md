## Can't be on Vercel alone

The landing and web UI can use Vercel, but the Phase 1 architecture also requires long-running or stateful services:

- `core-api`, `workers`, `messaging-gateway` and `ai-service` run as separate container deployables.
- PostgreSQL/PostGIS/pgvector and the cache/state Redis instances need managed stateful hosting.
- Workers and the gateway need durable queues, background execution and webhook processing; AI jobs can outlive a serverless request.

## Order to switch on

1. **Secrets, KMS and hosting foundations.** Establish IAM, managed keys, PostgreSQL, Redis, backups and networking before any personal data enters production.
2. **File storage.** Create encrypted buckets and lifecycle deletion so voice and media have a compliant destination.
3. **Email.** It supports pilot requests and operational contact with the smallest integration surface.
4. **SMS / OTP.** Authentication needs an approved sender and delivery monitoring before inviting a pilot centre.
5. **Maps / geocoding.** Enable centre discovery after billing caps and location privacy controls are set.
6. **Speech-to-text.** Benchmark Egyptian Arabic and approve the vendor's data terms before sending any real recording.
7. **The LLM.** Turn it on only after redaction, leak checks, budgets and no-training/retention terms are verified.
8. **Payments.** Complete merchant onboarding, webhook verification, reconciliation and refund tests before charging anyone.
9. **WhatsApp.** Add it after consent capture, approved templates, STOP handling and staff approval are working; the architecture places it in Phase 2.
