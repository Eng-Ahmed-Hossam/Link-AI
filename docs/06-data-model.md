# 06 · Data model

PostgreSQL 16+ with PostGIS and pgvector. This file mirrors the Eraser ERD (diagram 03, `vDhZGbDt1rtl9jEXJ0Aw`). It adds the tables and columns the rules need; each addition is marked **(added)**. Every change from the ERD is listed in §12.

## 0. Conventions

| Topic | Rule |
|---|---|
| Schemas | One per bounded context: `identity`, `ref`, `org`, `market`, `ledger`, `records`, `followup`, `messaging`, `analytics`, `audit`, `platform` (see [05-architecture.md](05-architecture.md) §2). |
| Keys | `id uuid` primary key, UUIDv7 generated by the app. |
| Names | `snake_case`. Plural table names. Foreign keys are `<entity>_id`. |
| Money | `bigint`, suffix `_pt` (piasters). `CHECK (… >= 0)` unless a sign is meaningful. Never `numeric` or `float` for money. |
| Rates | `numeric(5,2)` percent (e.g. `5.00`). Snapshotted onto the row that used them. |
| Time | `timestamptz` with suffix `_at`. Dates are `date` with suffix `_on`. Schedules are stored in UTC and shown in `Africa/Cairo`. |
| Enums | `text` + `CHECK (col IN (…))`. Easier to migrate than Postgres enums. |
| Extensions | `CREATE EXTENSION postgis; CREATE EXTENSION vector; CREATE EXTENSION btree_gist;` — `btree_gist` is required by the exclusion constraints on `room_open_slots`, `room_booking_slots` and `commission_rules` (they mix `=` on scalar columns with `&&` on ranges). |
| NULLs in keys | In PostgreSQL `NULL` never equals `NULL`. Every unique constraint over a column that may be NULL uses **`UNIQUE NULLS NOT DISTINCT`** (PostgreSQL 15+). Exclusion constraints can't do that, so they use a generated, non-NULL scope column instead (see `commission_rules.scope_id`). |
| Tenancy | Every tenant table has `centre_id uuid NOT NULL`. It is copied from the parent row and kept equal to it by a trigger. RLS uses it. Exception: `ledger.payments.centre_id` is NULL for a paid-extras subscription bought by a teacher only. |
| Cross-schema refs | Plain `uuid`, no FK (module rule 4). Within a schema: real FKs. |
| Personal data | Marked **[PII]**. Phone numbers outside `identity.users` are encrypted at the app level (`bytea`), with an HMAC column for lookup. |
| Deletes | Business rows are archived (`archived_at`). Append-only tables reject `UPDATE` and `DELETE` with a trigger and have no grants for them. |
| Common columns | `created_at timestamptz NOT NULL DEFAULT now()` everywhere. `updated_at` on mutable tables. Not repeated below. |

### RLS policy codes

Each request sets the context with `SET LOCAL`: `app.user_id`, `app.roles`, `app.centre_ids` (centres where the user is owner or staff), `app.teacher_id`, `app.guardian_id`. The app connects as `app_user`, which has **no** `BYPASSRLS`. Workers connect as `app_worker`, with policies per job. Ops connect as `app_ops`.

| Code | Policy (read unless stated) |
|---|---|
| `PUBLIC` | Anyone, but only rows that are public (verified / published / listed). Public reads go through views in `market` that expose only public columns. |
| `SELF` | `user_id = app.user_id` |
| `CENTRE` | `centre_id = ANY(app.centre_ids)`. Writes also need the matching permission. |
| `TEACHER` | `teacher_id = app.teacher_id` |
| `GUARDIAN` | The row's `student_id` is linked to `app.guardian_id` in `org.student_guardians`, or `guardian_id = app.guardian_id`. |
| `OPS` | `'link_ops' = ANY(app.roles)`. Every read of personal data is audited. Writes only through ops endpoints. |
| `SYSTEM` | `app_worker` only. No user access. |

## 11. Invariants (tested in CI)

| # | Invariant | Enforced by |
|---|---|---|
| INV-01 | For every ledger transaction, Σ debit = Σ credit. | Deferred constraint trigger + property tests |
| INV-02 | Ledger entries, audit events, consent events, corrections and topic-mastery snapshots are never updated or deleted. | Triggers + no grants |
| INV-03 | A payment's capture transaction credits exactly `amount_pt` in total. | Posting service + test |
| INV-04 | Rent invoice: net = gross − fee; deducted + top-up ≤ gross; paid ⇔ equal. | CHECK constraints |
| INV-05 | For every `group_session`: live enrolments covering it + live holds covering it + `offered` waitlist entries covering it ≤ the group's `seat_cap`; and `seat_cap` ≤ hall capacity. | Redis enforces the whole formula atomically (08 §4). Holds live only in Redis, so the DB trigger counts what Postgres stores — committed enrolments + `offered` waitlist entries — per session. A nightly job rebuilds the `seats:` counters from the database |
| INV-06 | Two live bookings never overlap in the same hall. | Exclusion constraint (`btree_gist`) |
| INV-07 | At most one live enrolment (`pending_payment`, `awaiting_teacher`, `confirmed`, `past_due`) per student per group. | Partial unique index |
| INV-08 | At most one open flag per rule, student, group and topic. | Partial unique index, `NULLS NOT DISTINCT` |
| INV-09 | Confirmed record entries change only through `corrections`. | Trigger |
| INV-10 | A score is never above its maximum. | Trigger / CHECK |
| INV-11 | No message is queued or sent without `approved_by`. | CHECK |
| INV-12 | Every tenant row's `centre_id` equals its parent's. | Triggers |
| INV-13 | Commission rules of the same kind and scope never overlap in time — including the global default. | Exclusion constraint on `(kind, scope_id, validity)` (`btree_gist`) |
| INV-14 | `payouts.net_pt = Σ payout_items.amount_pt`; one payout per payee per period. | Constraint trigger + `UNIQUE NULLS NOT DISTINCT` |
| INV-15 | Teacher and centre payable balances are never negative, except after a chargeback (P9) or a rent reversal on an already-paid-out centre balance (P12); both are flagged to ops. | Posting service + nightly check |
